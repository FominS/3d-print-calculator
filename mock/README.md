# Демо-данные и демо-режим

Фейковые данные для ручного тестирования и отладки PrintBench. Покрывают все экраны и состояния интерфейса, так что на любом экране есть на что посмотреть.

## Запуск

```
python -m http.server 8000
```

| Адрес | Что происходит |
|---|---|
| http://localhost:8000/?demo | приложение на демо-данных; изменения сохраняются между перезагрузками |
| http://localhost:8000/?demo=reset | песочница сбрасывается, демо-данные создаются заново (даты — от сегодняшнего дня) |
| http://localhost:8000/?demo#printer/p2s | любой раздел: хэш работает как обычно |
| http://localhost:8000/ | обычный режим с вашими настоящими данными |

В правом нижнем углу демо-режима — плашка «ДЕМО-данные» с кнопками «Сбросить» и «Выйти».

Язык демо-данных берётся из языка интерфейса в момент создания. После переключения RU/EN нажмите «Сбросить», чтобы пересоздать данные на новом языке.

## Изоляция от настоящих данных

- `localStorage`: все ключи получают префикс `pbdemo:`; общими остаются только тема (`p2s_theme`) и язык (`p2s_lang`).
- IndexedDB: база `p2s_cost` подменяется на `p2s_cost_demo`.
- Подключение папки на компьютере и Google Drive в демо отключено, чтобы демо-данные случайно не записались в настоящее хранилище.
- Bambu Lab Cloud заменён фейком: сетевых запросов к прокси нет.

## Файлы

| Файл | Назначение |
|---|---|
| `demo-data.js` | генератор данных: `PB_DEMO_DATA.build(lang)` возвращает объект в формате `3d-print-data.json` (version 5) |
| `demo.js` | включение демо-режима: изоляция хранилищ, заполнение песочницы, плашка |
| `bambu-mock.js` | фейковый `window.Bambu`: принтеры, текущая печать, прошивка, история заданий, катушки RFID, «Сейчас в AMS» |

Скрипты подключаются из `index.html` только при параметре `?demo`. Без него приложение их не загружает.

## Что есть в данных

- **Принтеры.** Bambu Lab P2S (в сети, печатает, доступно обновление прошивки, работы «пора» и «скоро», одна работа отключена, у одной своя периодичность). A1 mini (не в сети, чтение AMS возвращает ошибку). Creality Ender-3 V3 (без облака, обслуживание запущено). В облачном аккаунте есть свободный X1C, его можно связать с Ender.
- **AMS у P2S.** Катушка с RFID узнаётся сама; сторонняя катушка привязана к слоту; ещё одна сторонняя не сопоставлена, для неё есть подсказка; PLA-CF сейчас подаётся; TPU стоит на внешней катушке.
- **Материалы.** PLA, PETG, ABS, ASA, TPU, PLA Silk и абразивный PLA-CF (он сокращает интервал проверки ножа).
- **Катушки.** Есть все статусы: запечатанные, открытые, закончившиеся. Есть катушки с RFID и без, многоцветная, с отзывами и оценками, с ручными операциями (взвешивание, списание). Несколько катушек ниже порога «заканчиваются».
- **Изделия.** Все статусы: идея, в работе, готово, опубликовано. Органайзер собран из вложенных изделий в два уровня. Есть изделия из нескольких материалов, с доп. затратами, ссылками, описанием, профилем печати и тегами.
- **Журнал печати** примерно за 5 месяцев (текущий месяц заполнен плотнее). Есть:
  - столы из нескольких изделий, в том числе с долями, заданными вручную;
  - серия прототипов с версиями;
  - неудачные печати и неудачная деталь на столе;
  - печати без изделия и печать «со всеми вложенными»;
  - записи, импортированные из Bambu Cloud.
- **История Bambu Cloud.** Часть заданий уже импортирована, остальные новые: успешные, с ошибкой и идущее сейчас. Модель из двух столов импортируется как сборка. В списке катушек RFID есть катушки, которые уже на складе, и новые.

Фотографий нет: файлы фото хранятся в подключённом хранилище, а оно в демо отключено.

## Как менять

Правьте `demo-data.js` и откройте `?demo=reset`. Хелперы в начале файла:

- `d(n)` — дата n дней назад;
- `at(n, h, m)` — ISO-время n дней назад;
- `P(...)` — добавить запись журнала.

Остатки катушек нигде не задаются: приложение вычисляет их из `net`, ручных операций `ops` и расхода в записях журнала.

Если схема данных изменилась и старая песочница мешает, увеличьте `SEED_VER` в `demo.js`. Тогда у всех песочница пересоздастся при следующем открытии `?demo`.
