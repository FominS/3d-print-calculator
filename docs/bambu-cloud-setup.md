# Импорт истории печати из Bambu Lab Cloud — пошагово

Сайт может загружать историю печати принтера Bambu Lab (P2S, P1S, X1, A1 и др.) прямо в журнал: название модели, дата, фактическое время, результат (успех или ошибка), расход филамента по слотам AMS с цветом и типом пластика.

## Как это устроено

```
Сайт (GitHub Pages) ──► Ваш Cloudflare Worker ──► api.bambulab.com
        ▲                  (добавляет CORS)            │
        └──────────────── история печати ◄─────────────┘
```

- Историю печати хранит **облако Bambu Lab**, а не сам принтер. По локальной сети принтер сообщает только текущее состояние, списка прошлых печатей у него нет.
- Bambu Cloud не разрешает браузеру обращаться к нему с других сайтов (нет CORS). Поэтому нужен маленький посредник, **Cloudflare Worker**. Он бесплатный: в тарифе Free 100 000 запросов в день, а импорт тратит 2–3 запроса.
- Worker ничего не хранит и не записывает. Он пропускает только 7 адресов API (вход, код на почту, история печати, список принтеров, катушки AMS, прошивка, текущая печать), чтение состояния AMS по MQTT и картинки заданий с серверов Bambu Lab и только с вашего сайта.
- API Bambu Lab **неофициальное** (его описало сообщество: [OpenBambuAPI](https://github.com/Doridian/OpenBambuAPI)) и может измениться.

Настройка занимает около 10 минут, делается один раз.

---

## Шаг 1. Создать Worker в Cloudflare

1. Зарегистрируйтесь на https://dash.cloudflare.com/sign-up (бесплатно, домен не нужен).
2. Слева: **Compute (Workers)** → **Workers & Pages** → **Create** → **Create Worker** («Start with Hello World»).
3. Name: `bambu-proxy` → **Deploy**.
4. Нажмите **Edit code**. Удалите весь пример и вставьте содержимое файла [`worker/bambu-proxy.js`](../worker/bambu-proxy.js) из этого репозитория → **Deploy**.
5. Скопируйте адрес Worker. Он выглядит так: `https://bambu-proxy.<ваше-имя>.workers.dev`.

### 1а. Разрешить свой сайт

По умолчанию Worker отвечает только сайту `https://fomins.github.io`. Если сайт открыт по другому адресу (свой форк на GitHub Pages или локальный запуск):

1. В Worker: **Settings** → **Variables and Secrets** → **Add**.
2. Type: **Text**, Variable name: `ALLOWED_ORIGINS`, Value: адреса через запятую, без `/` в конце, например
   `https://fomins.github.io,http://localhost:8000`
3. **Deploy**.

> Вариант для командной строки: `npx wrangler deploy` из папки `worker/` (в ней лежит `wrangler.toml`).

## Шаг 2. Указать адрес Worker на сайте

Любой из двух способов:

- **На сайте:** «Настройки → Bambu Lab Cloud → Адрес прокси». Адрес сохранится в этом браузере.
- **Для всех устройств:** впишите адрес в `js/config.js` → `bambuProxy: 'https://bambu-proxy.<ваше-имя>.workers.dev'`, затем commit и push.

Адрес Worker не секрет: без токена Bambu через него ничего не получить.

## Шаг 3. Войти в Bambu Lab Cloud

1. «Настройки → Bambu Lab Cloud». Регион: **Глобальный**. **Китай** нужен только для аккаунтов bambulab.cn.
2. Введите email и пароль от аккаунта Bambu Lab (те же, что в Bambu Handy или Bambu Studio) → **Войти**.
3. Bambu Lab обычно просит подтвердить вход кодом из письма. Код придёт на почту, введите его → **Подтвердить**.
   Можно войти и без пароля: кнопка **Войти по коду из письма**.
4. Появится «● Подключено · токен до …». Токен действует около 3 месяцев, потом войдите снова.

**Что хранится и где:** пароль не сохраняется нигде. Токен хранится только в этом браузере (`localStorage`) и **не попадает** в файл данных и Google Drive. На другом устройстве нужно войти отдельно. Токен даёт полный доступ к аккаунту Bambu: не открывайте сайт на чужих компьютерах без последующего «Выйти».

### Если включена двухфакторная аутентификация

Вход с 2FA сайт не поддерживает. Токен можно вставить вручную («Ввести токен вручную»). Обычно его можно взять так: войдите на https://bambulab.com в браузере, откройте инструменты разработчика (F12) → **Application** → **Cookies** → `https://bambulab.com` → значение cookie `token`.

## Шаг 4. Импорт в журнал

1. «Журнал печати» → **⇣ Из Bambu Cloud**.
2. Вверху выберите принтер аккаунта (или «Все принтеры») и принтер калькулятора, на который записывать печати. Выбор запомнится.
3. Для каждого задания сайт сам подставит:
   - **изделие** — по совпадению названия модели или файла с названием в каталоге (можно изменить или оставить «без изделия»);
   - **катушку** — по типу пластика и цвету из AMS (ближайший цвет среди катушек этого материала). Если подходящей катушки нет, пластик учтётся только по цене материала, без списания;
   - **граммы** — расход по каждому слоту AMS. Для неудачной печати расход уменьшается пропорционально фактическому времени печати;
   - **время** — фактическое (окончание − начало). Если оно неизвестно, берётся оценка слайсера.
4. Отметьте нужные задания → **Импортировать**.

Уже импортированные задания отмечаются «в журнале» и повторно не импортируются. Задания, которые печатаются прямо сейчас, импортировать нельзя: откройте импорт после окончания печати. За один раз загружаются последние 100 заданий.

## Шаг 5. Сверка катушек Bambu Lab (RFID)

AMS считывает RFID-метки фирменных катушек Bambu Lab и передаёт в облако оценку остатка. Эти данные можно перенести в раздел «Филаменты».

1. «Филаменты» → **⇣ Сверить с Bambu Cloud**.
2. Для каждой катушки из облака сайт подберёт вашу по типу пластика (строго: `PLA-CF` не равно `PLA`), цвету, серии и производителю. Рядом показано, что изменится, например «остаток 948 → 610 г · статус → Открыта».
3. Если пары нет, предлагается **создать новую катушку**: производитель Bambu Lab, серия, цвет, вес и остаток из облака. Цену и магазин допишите в её карточке. Если такого материала в настройках нет, он создастся без цены, и сайт об этом предупредит.
4. Можно выбрать другую катушку или «Пропустить». Затем нажмите **Применить**.

Что происходит при применении:
- в катушку записывается операция **«Установлен остаток» (Bambu Cloud)**. Печати после неё списываются уже от этого значения, поэтому импорт истории и сверка не считают граммы дважды;
- закончившаяся катушка получает статус «Закончилась», а запечатанная, которая стоит в AMS, — «Открыта»;
- связь запоминается, и при следующей сверке катушка подбирается сразу. Совпадающие катушки скрыты, их можно показать галочкой «показывать без изменений».

Ограничения:
- видны только катушки Bambu Lab с RFID, которые AMS хоть раз считывал. Запечатанные запасные и катушки других производителей облако не знает;
- остаток — это оценка AMS, а не взвешивание; со временем она может расходиться с реальностью;
- уникального номера катушки облако не отдаёт, поэтому две одинаковые катушки (одна серия, цвет и вес) сайт различает только по порядку. Проверьте их привязку при первой сверке.

> Если Worker создан до появления сверки катушек, обновите его код: вставьте заново `worker/bambu-proxy.js` (шаг 1, п. 4) и нажмите Deploy. Иначе появится ошибка «route not allowed».

## Шаг 5а. Изделия и элементы из печати

**Привязка печати к изделию и элементу.** У каждой записи журнала кнопка **⛓ Изделие**: выберите изделие, затем — что напечатано этой печатью:
- **Изделие целиком** — запись считается как комплект;
- **один из элементов** (детали) изделия — например, только крышка или один из столов;
- **новый элемент из этой печати** — в изделие добавится деталь с временем и граммами из печати.

Если подходящего изделия нет — «+ Новое изделие из этой печати». То же можно выбрать прямо в окне импорта: «＋ Создать новое изделие» или «Что напечатано → ＋ Новый элемент».

Комплекты в карточке изделия считаются по элементам: «Напечатано комплектов: 1 · по элементам: Основание — 1 шт, Крышка — 2 шт».

**Картинки.** Обложка задания из Bambu Cloud показывается в журнале печати. Когда из печати создаётся изделие, картинка сохраняется в фото изделия (нужно подключённое хранилище — папка или Google Drive).

**Модели из истории.** «Изделия → ⇣ Модели из Bambu Cloud»: задания из истории группируются по модели (MakerWorld) с картинкой, числом печатей и столами (plate). Для каждой модели — «Создать изделие» (каждый стол станет элементом с временем и граммами из печати, ссылка на MakerWorld добавится сама) или «Связать» с существующим. Галочка «привязать записи журнала» сразу привяжет импортированные печати к изделию и элементам по столам. Учитываются последние 100 заданий.

> Для картинок Worker должен пропускать адрес `/img`. Если Worker создан раньше, вставьте заново `worker/bambu-proxy.js` и нажмите Deploy.

## Шаг 6. Принтер: состояние и обслуживание

Раздел **«Принтер»** (в меню «Дополнительно»):

- **Состояние** — наработка, загрузка в часах в день, число печатей и доля успешных, ресурс амортизации. Если принтер связан с Bambu Cloud, видно, в сети ли он, текущую печать с прогрессом и оставшимся временем, версию прошивки и доступное обновление, а также сколько заданий в облаке ещё не импортировано.
- **Обслуживание** — регламент Bambu Lab для P2S: смазка осей X/Y и Z (интервал подбирается по загрузке), натяжные ролики, воздушный фильтр (1440 ч), нож филамента (по израсходованным килограммам), камера и работы «по состоянию». Кнопка «✓ Выполнено» отмечает работу сегодняшней датой, в «История и настройка» можно указать прошлую дату, свой интервал или отключить работу.
- **Статистика** — часы, печати, доля успешных и филамент по месяцам.

Связать принтер с облаком: «Принтер → Состояние → Связать с …» или «Настройки → Принтеры → Принтер в Bambu Cloud».

Наработка считается по журналу печати и прототипам. Счётчика моточасов в облаке нет, поэтому часы, напечатанные до начала учёта, впишите в «Настройки → Принтеры → Наработка до начала учёта», а дату покупки — в «В работе с».

> Для прошивки и текущей печати Worker должен пропускать ещё два адреса. Если Worker создан раньше, вставьте заново `worker/bambu-proxy.js` и нажмите Deploy.

### «Сейчас в AMS» (прототип)

Блок на вкладке «Принтер → Состояние» показывает, что стоит в каждом слоте AMS прямо сейчас, и сопоставляет слоты с катушками склада.

- По HTTP облако такие данные не отдаёт, их присылает сам принтер по **облачному MQTT**. Кнопка **↻ Прочитать AMS** просит Worker на несколько секунд подключиться к `us.mqtt.bambulab.com:8883` с вашим токеном, запросить у принтера полный отчёт (`pushall`) и вернуть слоты. Принтер должен быть в сети.
- **Катушки Bambu Lab** узнаются по уникальному номеру RFID (`tray_uuid`). Подтвердите один раз «Это «…»?» или выберите катушку в списке, и дальше она узнаётся в любом слоте и на любом принтере.
- **Сторонние катушки** видны с типом и цветом, которые вы задали на принтере или в слайсере. Их привязка запоминается для слота и действует, пока в нём те же тип и цвет. Если в слоте появилась другая катушка, сайт напишет «В слоте другая катушка».
- При привязке запечатанная катушка становится «Открытой».

> Нужен обновлённый Worker: вставьте заново `worker/bambu-proxy.js` и нажмите Deploy. Код использует `cloudflare:sockets` (TCP-подключение из Worker), его поддерживает и бесплатный тариф.
>
> API неофициальное. Прошивки с «Authorization Control» могут игнорировать команду `pushall`. Тогда P1/P2S/A1 присылают только изменения, а сайт пометит отчёт как неполный. Ошибка «mqtt connect refused» с кодом 5 означает, что облако не приняло токен для MQTT: войдите заново.

## Ошибки

| Сообщение | Что сделать |
|---|---|
| «Не задан адрес прокси» | Шаг 2. |
| «Прокси недоступен» | Проверьте адрес Worker (должен начинаться с `https://`, без `/` в конце) и что Worker задеплоен. |
| «Worker не разрешает этот сайт» | Добавьте адрес сайта в `ALLOWED_ORIGINS` (шаг 1а). |
| «Incorrect account or password» | Неверный email или пароль. Попробуйте «Войти по коду из письма». |
| «Токен истёк или отозван» | Войдите снова. Токен отзывается и при смене пароля Bambu Lab. |
| «route not allowed» при сверке катушек | Обновите код Worker (см. примечание в шаге 5). |
| Код не приходит | Проверьте «Спам», нажмите «Отправить код ещё раз» через минуту. |
